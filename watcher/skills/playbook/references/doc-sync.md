# 同步文档

流水线走到同步文档、做「删掉或改名所有 X」类清理、文案对抗和提 PR 前、写说明性文档时读。

## 1. 按全部表面形式检索全部副本

同步文档和做「删掉或改名所有 X」类清理时，把本次改动、删除、改名的名字，按全部表面形式（产品叫法、代码符号、文件名、数值，以及大小写和同义变体）检索所有相关仓库的全部 git 跟踪文件（含 living doc、注释、docs 目录），不只看 diff；逐处判那句话现在还成不成立。改了一句规矩，同样检索它的全部副本。

理由：被一次改动弄假的文字常常不在 diff 里；代码点位漏了有测试报，文字点位漏了没有任何东西报。

判定：本次删掉或改名了哪些名字？它们在各仓里还有几处在描述它？

## 2. 核断言的范围

文案对抗和提 PR 前核事实断言，范围包括代码注释、公开文档、内部设计与 living doc、PR 正文。核完再跟自己的任务清单对一遍；断言跟某条 todo 说反了，先信 todo 去核。

理由：PR 正文不在任何检查的覆盖范围内；todo 是当初查过才记下的。

判定：这句话能被一条命令或一次阅读证伪吗？能，它就需要本轮的证据。

## 3. 怪异现状先判再写

给怪异的现状写来历或兼容说明之前，先判它是本质必要还是历史多余（检索同类，看它是不是唯一的特例）；多余的先消除再写。

理由：准确记录一个不该存在的状态，等于给它背书。

判定：这个差异是本质必要，还是只此一处的历史遗留？
