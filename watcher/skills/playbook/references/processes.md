# 起进程、造负载、清进程

起开发服务或任何长活进程、为复现问题造负载、起临时后台进程、清进程时读。这里只写决策；具体命令写在项目 skill 里。

## 1. 长活进程脱离当前任务

希望比当前命令活得久的进程，脱离当前任务和会话启动；起完确认它真的脱离了，端口能连通不算确认。

理由：挂在任务下面的进程，会在任务被清理时一起终止。

判定：当前任务结束时，这个进程会不会一起被终止？

## 2. 负载自带结束时间

实验造负载只用自带结束时间的写法，不用没有终点的循环。长活进程的清理单独作为一步做，不写在起它的那条命令后面。

理由：清理那一行会不会执行，不由你决定；没有终点的进程会一直占着资源，还会造出跟改动无关的测试失败。

判定：没人杀它会怎样？答「一直跑」就换写法。

## 3. 只清自己起的进程

只清自己起的进程：起的时候记下进程号，清的时候按进程号逐个清，不按名字模式批量清。清理命令的报错不吞掉。

理由：按名字匹配会误杀别人的进程；吞掉报错就看不见清理失败。

判定：要清的这个进程号，是起它时记下的吗？
