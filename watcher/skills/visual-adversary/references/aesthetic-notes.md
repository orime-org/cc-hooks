# 视觉效果建议的素材

这一页是建议的**素材**，不是结论。每条都要落到「这个页面上具体差在哪」才能进建议表。

举例说明区别：

| 写法 | 能不能用 |
|---|---|
| 「字体数超过 3，违反规范」 | 不能。这是结论，没说换了之后效果差在哪 |
| 「这个页面用了 4 种字体：标题 Playfair、正文 Inter、代码 Mono、两处标签用了 Lato。标题和正文的层级靠字号已经分得开，Lato 只出现在标签上，去掉它标签会跟正文同族但字号更小，层级仍在，整页少一种字体载入」 | 能。说清了现在什么效果、去掉什么效果、代价 |

项目的视觉规范写了同类要求时，那一条的参照物从「通行做法」变成「项目规范」，仍然按建议处理，只是理由里可以引规范原文。

来源是本机已装的 `design-review` 和 `plan-design-review` 两个 skill 的检查清单。它们把这些写成硬规则，这里只当观察角度用。

## 1. 排版

| 提示 | 出处 |
|---|---|
| 字体族数量控制在 3 以内 | design-review 第 2 类 |
| 字号阶遵循比例（1.25 大三度 / 1.333 纯四度） | 同上 |
| 行高：正文 1.5 倍，标题 1.15 到 1.25 倍 | 同上 |
| 每行 45 到 75 字符，66 为佳 | 同上 |
| 标题层级不跳级（h1 直接到 h3） | 同上 |
| 至少两种字重拉开层级 | 同上 |
| 标题用 `text-wrap: balance` 或 `text-pretty` | 同上 |
| 用弯引号，省略号用 `…` 而非三个点 | 同上 |
| 数字列用 `font-variant-numeric: tabular-nums` | 同上 |
| 小写文字不加字间距 | 同上 |

## 2. 色彩

| 提示 | 出处 |
|---|---|
| 非灰色控制在 12 种以内 | design-review 第 3 类 |
| 语义色一致（成功绿、错误红、警告黄） | 同上 |
| 不靠颜色单独编码信息，配文字、图标或纹理 | 同上 |
| 暗色模式用高度区分层级，不是简单反色 | 同上 |
| 暗色模式文字用偏白（约 `#E0E0E0`）而非纯白 | 同上 |
| 暗色模式主色降饱和 10 到 20 个百分点 | 同上 |
| 中性色统一偏暖或偏冷，不混用 | 同上 |
| 避免红绿单独组合（约 8% 男性红绿辨色力弱） | 同上 |

## 3. 布局

| 提示 | 出处 |
|---|---|
| 圆角有层级，不是所有元素同一个大圆角 | design-review 第 4 类 |
| 嵌套元素内圆角 = 外圆角 − 间隙 | 同上 |
| 正文有最大宽度，不通栏 | 同上 |
| 关联元素靠近，区块之间拉开 | 同上 |
| 刘海屏用 `env(safe-area-inset-*)` | 同上 |
| 断点用 375 / 768 / 1024 / 1440 | 同上 |
| 布局用 flex 或 grid，不用 JS 量尺寸 | 同上 |

## 4. 交互状态

| 提示 | 出处 |
|---|---|
| 所有可交互元素有 hover 态 | design-review 第 5 类 |
| 按下态有深度或色彩变化 | 同上 |
| 禁用态降透明度加 `cursor: not-allowed` | 同上 |
| 骨架屏形状贴合真实内容布局 | 同上 |
| 空状态给文案 + 主操作 + 视觉，不只写「暂无数据」 | 同上 |
| 错误信息说清发生了什么、为什么、下一步做什么 | 同上 |
| 每个决策点都是「不用想」的点击 | 同上 |

## 5. 动效

| 提示 | 出处 |
|---|---|
| 进场用 ease-out，退场用 ease-in，位移用 ease-in-out | design-review 第 7 类 |
| 时长 50 到 700ms | 同上 |
| 每个动画都在传达信息（状态变化、注意力、空间关系） | 同上 |
| 只动 `transform` 和 `opacity`，不动 width/height/top/left | 同上 |

## 6. 文案

| 提示 | 出处 |
|---|---|
| 按钮文字具体（「保存 API Key」而非「继续」「提交」） | design-review 第 8 类 |
| 用主动语态 | 同上 |
| 加载态末尾用 `…` | 同上 |
| 破坏性操作有确认或撤销窗口 | 同上 |
| 删掉开场白式的欢迎语和自夸文字 | 同上 |
| 可见说明超过一句话，说明交互本身有问题 | 同上 |

## 7. AI 生成感

design-review 第 9 类列的反模式：

| 反模式 |
|---|
| 紫罗兰渐变背景、蓝到紫配色 |
| 三列等宽功能卡（彩色圆圈图标 + 粗标题 + 两行描述） |
| 彩色圆圈里的图标作为区块装饰 |
| 所有标题和描述都居中 |
| 所有元素同一个大圆角 |
| 装饰性色块、浮动圆圈、波浪分隔线 |
| emoji 当设计元素 |
| 卡片左侧彩色竖条 |
| 「欢迎来到 X」「解锁 X 的力量」这类首屏文案 |
| 固定节奏的区块顺序（首屏 → 三个功能 → 评价 → 定价 → CTA） |
| `system-ui` 或 `-apple-system` 作为主要显示字体 |

## 8. 性能

| 提示 | 出处 |
|---|---|
| LCP 低于 2.0 秒（应用）/ 1.5 秒（内容站） | design-review 第 10 类 |
| CLS 低于 0.1 | 同上 |
| 图片带 `loading="lazy"` 和宽高，用 WebP 或 AVIF | 同上 |
| 字体 `font-display: swap`，关键字体预加载 | 同上 |

## 9. 来源里写成禁令的几条

两个来源 skill 把下面几条写成了硬规则：

| 原文 | 出处 |
|---|---|
| 「Banned Fonts: Inter, Roboto, Arial, Open Sans, Helvetica」 | high-end-visual-design |
| 「No default font stacks (Inter, Roboto, Arial, system)」 | plan-design-review 通用规则 |
| 「If primary font is Inter/Roboto/Open Sans/Poppins → flag as potentially generic」 | design-review 第 2 类 |

这类禁令在这里降为观察角度。字体本身没有对错，能说的是它在这个页面上的实际效果 —— 比如「正文用 Inter，跟同类产品撞脸，换成 Source Serif 后正文更有阅读感、跟标题的无衬线形成对比，代价是要多载入一个字族、且 Serif 在小字号下清晰度略低」。项目 token 指定了某款字体时，这条的参照物就是项目规范。
