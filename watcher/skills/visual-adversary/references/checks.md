# 看什么

## 1. 必改：可访问性和可用性

数据在 `checks` 里，直接读。

| 项 | 标准 | 字段 |
|---|---|---|
| 正文对比度 | ≥ 4.5:1 | `contrast`，`need` 为 4.5 的 |
| 大字对比度 | ≥ 3:1（≥24px，或 ≥18.66px 且 ≥700 字重） | `contrast`，`need` 为 3 的 |
| 触控目标 | ≥ 24×24（WCAG 2.2 SC 2.5.8 AA） | `targets`，句子里的链接已按标准的 Inline 例外排除 |
| 内容不被裁掉 | 无隐式溢出 | `clipped`、`documentOverflowX` |
| 允许缩放 | 无 `user-scalable=no`、`maximum-scale=1` | `viewportUserScalable` |

图标、SVG、边框的对比度这份数据不覆盖 —— 只算带文字的元素。暗色下看不清的图标要靠截图看出来。

## 2. 建议：跟项目一不一致

| 项 | 数据 |
|---|---|
| 哪些值没走 token | `offToken`，按颜色、字号、间距、圆角、阴影、动效时长分组 |
| 页面用了几种字号、几种间距 | `used`，去重后的列表。种类多得离谱本身就是信号 |
| 本可以用已有组件的地方 | 读改动文件的源码，看用了裸 `<button>` 还是项目的 `Button` |

`offToken` 里有三类东西不是问题：浏览器默认样式、第三方组件库的内部样式、内容驱动的值（图表配色、用户自定义主题）。看截图分辨比看数据快。

## 3. 建议：看着怎么样

没有数据，靠看截图。角度在 [aesthetic-notes.md](aesthetic-notes.md)。

| 角度 | 看什么 |
|---|---|
| 层级 | 一屏之内先看到什么、后看到什么，是不是想要的顺序 |
| 密度 | 信息块之间有没有喘息，扫视时能不能分出组 |
| 节奏 | 同类区块的高度、间距有没有规律 |
| 配色关系 | 主色用在哪几处，散得太开就失去重点 |
| 状态区分 | hover、选中、禁用之间的差别看不看得出来 |

## 4. 建议：跟 demo 差在哪

两张图逐处对，标出差异位置和差异量，顺带说哪一版在这个场景下更合适 —— 实现比 demo 好是常有的事。

## 5. 证据怎么写

必改项，三个数：

```
span.hint ｜ 标准 4.5:1 ｜ 实测 3.8:1 ｜ 前景 rgba(0,0,0,0.45) 合成后 rgb(140,140,140)，背景 rgb(255,255,255)
button.icon ｜ 标准 24×24 ｜ 实测 20×20 ｜ 差 4px
```

建议项，说清换了之后有什么不同：

```
三张卡片间距 16px ｜ 四块挤在一起，扫视没有停顿点 ｜ 24px 后每块有喘息，一眼分出组 ｜ 首屏从 6 张降到 4 张
.btn-primary 背景 rgb(37,99,236)，色板是 rgb(37,99,235) ｜ 肉眼无差别，但不随主题切换，暗色下会保持亮蓝 ｜ 走 token 后跟主题变 ｜ 无
Settings.tsx:42 用了裸 button ｜ 项目 Button 有 loading 态和统一焦点环，这里都没有 ｜ 换成 Button 后两者都有 ｜ 多传两个 props
```

看不出「换了之后有什么不同」的不写。「不符合规范」「不够高级」「主流不这么做」这类没有效果描述的不写。
