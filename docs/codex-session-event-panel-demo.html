Codex 任务面板会话事件演示

在项目当前目录运行 codex 或 codex resume。面板启动先显示等待，首次原生事件到达后加载当前会话的任务。标题和状态栏由你设置。

自上而下的数据流

WezTerm 识别当前 pane 中运行的 Codex
↓
底部创建三行面板，登记本地进程与父 pane
↓
你提交首条消息，Codex 的原生 hook 提供 session_id
↓
插件在内部关联实际 Codex 进程，面板按这个进程接入，读取该会话已有计划
↓
update_plan 的 PostToolUse 保存完整计划，现有面板刷新

状态与操作

面板最多显示四条任务。真实终端先点击面板，再按上下键滚动；m 切换手动高度，a 恢复自动高度。当前 q 操作在本次 Codex 运行期间保持关闭，重新进入会话后再次创建面板。

内部事件的到达顺序

顺序数据如何流转
面板先登记原生事件到达后，更新已有面板的内部绑定并加载该会话任务。
原生事件先到达插件按实际运行的 Codex 进程保存会话事件和任务；面板登记后读取同一进程对应的活动事件。
事件早于首次界面观察事件记录已存在的 Codex 进程，WezTerm 稍后观察并创建面板，再按该进程接入任务。
面板已关闭原生事件继续保存计划，当前运行保持关闭。

本页说明当前实现的状态和结构。项目当前目录中的新建、恢复、计划更新、清空和关闭已在隔离的官方 Codex 与 WezTerm 中验证。
