# 三项任务收尾与任务面板移除设计

## 1. 目标与依据

目标：通过三项简短收尾信息说明当前任务、实际阶段和工作纪律执行情况，并移除插件提供的 Codex WezTerm 任务面板。

本设计为待审查方案。用户已确认三项字段、长度、适用场景、维持现有 Stop 收尾机制及面板移除计划；实现和验证状态由后续执行记录确认。

| 用户确认的要求 | 对应结果 |
|---|---|
| 当前任务最多 20 字 | 表述本轮正在处理的任务 |
| 当前任务的阶段最多 20 字 | 表述当前实际执行的流程环节 |
| 工作纪律自评最多 30 字 | 按事实写遵循情况，有偏离时写偏离及正确做法 |
| 三项正文合计最多 70 字 | 字段名和 Markdown 表格符号不计；标点、数字、英文字母各计 1 字 |
| 推进具体工作的收尾适用 | 设计、实现、审查、文档同步、smoke 等具体工作的最终回复补充三项 |
| 普通问答和讨论直接回答 | 按本轮实际工作判断；存在未完成任务或查阅资料本身不构成触发条件 |
| 现有规范继续约定其他汇报 | 审查结果、证据、确认事项等按现有规范表达 |
| Stop 保持正常收尾 | 格式及长度由 Agent 在结束前自行检查；审计沿用现有开关和手动调用约定 |
| 移除任务面板 | 移除面板运行入口、实现和配置技能，补齐已安装面板的移除说明 |

依据为本会话用户最终要求及“好的，计划不错，执行吧”的确认。此前讨论的七项格式已由本表替代。

## 4. 规则注入与呈现

在 `announce-intent.sh` 的表达章节末尾增加以下段落，继续由两个宿主共用该真源：

```text
2.4 任务收尾
2.4.1 本轮实际推进设计、实现、审查、测试、文档同步等具体工作时，收尾回复补充三项表格：当前任务≤20字、当前任务的阶段≤20字、工作纪律自评≤30字；正文合计≤70字，标点、数字和英文字母各计1字，字段名不计。
2.4.2 自评按本轮事实写遵循情况；有偏离写具体偏离及正确做法。普通问答和讨论直接回答。其他汇报遵循既有规范。格式和字数由Agent结束前自检，Stop沿用现有审计开关。
```

三项放在具体工作收尾回复的开头，使用两列表格；审查节点要求的“我建议……”按既有规范表达。阶段须与实际工作相符，例如“设计对抗”“实现与单元测试”“文档同步”“等待用户检查”。

| 项目 | 示例内容 |
|---|---|
| 当前任务 | 简化任务收尾并移除面板 |
| 当前任务的阶段 | 设计对抗 |
| 工作纪律自评 | 已按流程核对；审查结果待你确认 |

Agent 在写最终回复时按事实判定场景并自检。规范注入检查证明规则确实送达；真实任务和问答烟测观察实际回复。自然语言规则的遵循程度以实测说明。

### 4.1 注入长度

本轮拟定文本使共享规范从 9500 增至 9705 UTF-16 单元。`tests/check-size.sh` 的项目门槛拟改为 9800，保留距项目现有记载的宿主 10000 单元限制的 200 单元余量；脚本继续按真实完整 stdout 计数，提交前实跑。README 中的门槛与余量同步更新。Codex 的 `additionalContextLimit: 0` 沿用当前配置。

这是纯内部门槛取舍。判断依据为本轮确定的文本计数和已有长度门槛实现；设计审查核对新增文本、末尾换行及宿主限制的依据。实现时若实际输出达到门槛，先核查计数和内容，再按流程处理。

### 4.2 场景与流转

该功能由 Agent 在本轮收尾时判定场景，注入脚本沿用现有的消息提交处理。下面各行相互独立。

| 本轮处境或事件 | 最终回复结果 | 依据 |
|---|---|---|
| 用户讨论规则、询问概念，Agent 直接回答 | 直接回答 | 用户限定普通问答和讨论 |
| 为回答简单问题查阅一份文件 | 直接回答 | 用户限定本轮实际推进具体工作 |
| Agent 实际完成设计、实现、审查、同步或测试工作 | 按原规范汇报，开头补充三项 | 用户确认的工作场景 |
| 本轮既有问答又实际推进工作 | 工作收尾补充三项 | 依据“实际推进工作”的内部推断；设计审查重点核对 |
| Agent 检查发现内容超长或自评遗漏实际偏离 | 在发送前压缩并纠正为事实 | 用户要求字数上限及自行评估 |
| Agent 最终回复提交，进入 Stop | 现有 hook 按项目审计配置处理 | `suggest-watcher.sh` 现有分支 |

中文演示位于同目录 `round-summary-panel-retirement-demo.html`，展示工作收尾、普通问答和有偏离的自评，以及规则送达和面板移除路径。

### 5.1 已安装面板的退出步骤

正式插件更新及本机配置操作由用户执行。使用指南给出以下顺序；AI 在隔离配置中验证。

| 顺序 | 用户操作 | 完成结果 |
|---|---|---|
| 1 | 找到安装技能原先输出的实际 WezTerm 配置路径，备份该文件 | 原配置可恢复；默认路径选择沿用原安装器，显式自定义路径以安装记录为准 |
| 2 | 删除 `-- BEGIN cc-hooks task panel` 至 `-- END cc-hooks task panel` 的托管区段 | 配置正文和用户自定义设置保留 |
| 3 | 通过 WezTerm 的 ReloadConfiguration 操作重新加载配置 | 原面板的 Lua 事件处理器随配置重载清除 |
| 4 | 分别点击现有任务面板并按 `q` | 面板进程退出，对应底部窗格关闭 |
| 5 | 用户更新插件，并按宿主的插件加载方式刷新或重新进入会话 | 新发布包的共享 hook 接管后续消息 |
| 6 | 确认面板已退出后，清理插件数据目录下的 `task-panel-integration` 与 `task-panel` 专用目录 | 原面板运行副本与缓存清理完毕；同目录其他插件数据保留 |

移除标记区段前须先读实际文件。区段缺失、标记不完整或用户改写了加载方式时，说明查到的内容并询问当前用户如何处理，按答复操作。本文定义正常安装路径的退出方式。

WezTerm 官方说明：配置重载会重新建立 Lua 状态，从而清除旧事件处理器，见 [wezterm.on](https://wezterm.org/config/lua/wezterm/on.html)；[ReloadConfiguration](https://wezterm.org/config/lua/keyassignment/ReloadConfiguration.html) 提供原生重载操作。该说明用于退役现有集成；应用内实测留到受影响范围验证。

## 6. 方案依据与依赖

| 选择 | 依据 | 验证方式 |
